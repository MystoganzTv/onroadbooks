## Context

The forces at play. What was true about the product, the user or the code that
made a decision necessary. Written so someone who has never seen this repo can
follow it. No solution here.

## Decision

What we are doing, in the present tense and in as few sentences as it takes.
State the rule, not the implementation.

## Alternatives considered

**Option.** Why it was rejected -- the cost, not just the preference.

## Consequences

What follows from this. Include the parts that hurt: an ADR that only lists
benefits is a sales pitch, not a record.

## Guardrails

The things a future change must not break, phrased so a reviewer can check
them. This is the section people actually come back for.
